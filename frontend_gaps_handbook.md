## 3. Incomplete / Stubbed Features

### Message Loading -- FIXED

Both `ChannelTabsView` and `MobileChannelView` now use `useMessages(selectedAccountId)`
to fetch messages from the Frappe API when a thread is selected. The `selectedAccountId`
is the `ExcomThread.name` which serves as the `thread_id` for the messages API.

### Message Sending (Desktop + Mobile)

Both `ChannelTabsView` and `MobileChannelView` have message input and send
button, but `handleSendMessage` only clears the input. Needs:
- Call `excom.excom.api.chat.send_message` with thread_id, content, channel
- Optimistically append message to local state
- Handle delivery status updates via socket

### AI Assistant Integration

All AI features are purely presentational with static data:
- Suggested replies (desktop + mobile)
- Conversation summary
- Recommended next actions
- Quick insights (response patterns, engagement, best contact time)

Needs: AI backend API endpoint that accepts conversation context and returns
structured suggestions, summary, and insights.

### File Attachments

Paperclip and image buttons exist in both desktop and mobile conversation
views but have no implementation. Needs:
- File picker integration
- Frappe file upload API
- Media message type support in send_message

### Call Screen

The entire call screen is UI-only. It simulates connecting/ringing/active
states with timers but has no real communication backend. Needs:
- WebRTC or VOIP integration
- Call initiation and termination APIs
- Real audio/video stream handling

### Contact Data Enrichment (useContacts hook)

The hook groups threads into UnifiedContact objects but several fields are
always empty because the `get_threads` API doesn't return them:
- Avatar, email, company, ERP entity require Omni Identity / Contact joins
- Online/offline status needs realtime presence or last_seen
- AI status needs thread-level AI state tracking
- Assigned agent avatar needs User image lookup

### Mobile Navigation

Bottom tab bar only has "Chats" functional. "Calls" and "Contacts" tabs
are rendered but have no views or navigation logic.

### Account Switching (OmniIdentityPanel)

Account cards in the Omni Identity panel visually support click-to-switch
and pass `onAccountSwitch` callback, but the actual conversation reload
for the new account thread is not fully wired (messages don't refresh
for the switched account).
